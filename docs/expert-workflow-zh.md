# 专家任务采集与脱敏打包流程说明

这份文档说明专家在对话框里使用 agent 完成任务时，系统如何采集任务过程，并在任务结束后进行脱敏确认和 zip 打包。

专家不需要理解 trace、SQLite、git、trajectory 等底层概念。专家只需要按产品流程完成任务，系统在后台自动记录和整理。

## 一句话流程

```text
开始任务时启用采集
正常和 agent 协作完成工作
结束时发起打包
检查脱敏预览
确认后下载 zip 包
```

## 1. 开始任务

专家进入一个新任务对话框后，点击或输入：

```text
开始采集
```

系统会自动完成：

- 创建本次任务的任务 ID
- 开启对话轨迹记录
- 准备本地任务目录
- 初始化文件版本管理
- 开始记录 token 消耗

专家看到的提示可以是：

```text
已开始采集本次任务。
你可以正常和 agent 协作完成工作，系统会自动记录任务过程、输入文件、中间产物和版本变化。
```

## 2. 上传或指定输入文件

专家把任务需要的文件上传到对话框，或直接告诉 agent：

```text
请基于这份资料完成分析。
```

系统会把这些文件识别为输入文件，并自动记录：

- 文件名
- 文件类型
- 文件大小
- 文件 hash
- 文件内容快照
- 文件来源
- 记录时间

专家不需要手动记录输入文件。

## 3. 正常和 agent 协作

专家可以像平常一样和 agent 对话：

```text
先帮我梳理这份资料里的关键问题。
```

```text
把结果整理成一个报告草稿。
```

```text
这个口径不对，按新的要求重新生成一版。
```

```text
现在生成最终版。
```

系统在后台自动记录：

- 专家提出的需求
- agent 的关键执行步骤
- 使用过的工具
- 生成或修改过的文件
- 重要中间产物
- 每一步的 token 消耗
- 文件之间的版本变化

## 4. 自动保存关键版本

当任务过程中出现重要文件变化时，系统会保存版本快照。

常见快照节点包括：

- 上传输入文件后
- 生成初稿后
- 修改初稿后
- 生成二稿后
- 新增附件后
- 修改表格后
- 导出最终结果后

专家可以看到轻量提示，例如：

```text
已保存版本：报告初稿
```

```text
已保存版本：最终版候选
```

最终包里会保留同一文件的多个版本，而不是只保留最后一个文件。

## 5. 专家确认任务完成

当专家认为任务完成后，可以输入或点击：

```text
完成并打包
```

系统不会立刻生成最终包，而是先进入脱敏预览阶段。

## 6. 系统生成脱敏预览

系统会根据当前任务内容动态判断哪些信息需要脱敏。

系统会综合分析：

- 对话内容
- 输入文件
- 中间产物
- 最终文件
- 文件名
- 表头或字段名
- 业务上下文
- 生成结果

然后生成脱敏预览。

专家看到的提示可以是：

```text
已生成脱敏预览。
请检查脱敏后的文件和轨迹摘要，确认无敏感信息后再打包。
```

## 7. 专家检查脱敏结果

专家检查的是脱敏后的文件，而不是原始敏感文件。

界面可以展示：

```text
文件：final-report.docx
脱敏后路径：files/redacted/latest/final-report.docx
状态：已脱敏
发现项：12 处
```

专家需要确认：

- 是否还有敏感信息漏掉
- 是否误删了必要的业务信号
- 脱敏后的文件是否可以交付
- 轨迹摘要是否可以进入最终包

## 8. 确认或重新脱敏

如果专家认为脱敏结果没问题，可以点击或输入：

```text
确认脱敏，可以打包。
```

如果专家发现问题，可以要求系统重新处理：

```text
这里还有信息没有脱敏，请重新处理。
```

只要文件内容、任务上下文或脱敏策略发生变化，旧的确认都会失效，必须重新生成脱敏预览并再次确认。

## 9. 生成最终 zip 包

专家确认后，系统生成最终 zip 包：

```text
task-package.zip
```

zip 解压后结构如下：

```text
task-package/
  trajectory.json
  files/
    redacted/
      latest/
        final-report.docx
        analysis.xlsx
      versions/
        <version-1>/
          analysis.xlsx
        <version-2>/
          analysis.xlsx
        <version-3>/
          final-report.docx
```

其中：

- `trajectory.json` 记录任务过程、文件版本、token 消耗、脱敏摘要和确认信息
- `files/redacted/latest/` 放最新的脱敏后文件
- `files/redacted/versions/` 放历史版本的脱敏后文件
- zip 包不包含原始敏感值
- zip 包不包含原始 trace 数据库
- zip 包不包含脱敏映射表
- zip 包不包含临时文件和依赖目录

## 10. 下载或提交最终包

专家最终拿到：

```text
task-package.zip
```

界面提示可以是：

```text
最终包已生成。
该包已通过脱敏预览确认，包含任务轨迹、token 消耗、文件版本和脱敏后的交付文件。
```

## 专家需要记住什么

专家只需要记住 5 个动作：

```text
1. 开始采集
2. 上传文件或说明任务
3. 正常和 agent 协作
4. 完成后检查脱敏预览
5. 确认后下载 zip 包
```

其余事情由系统自动完成。

## 系统需要保证什么

系统需要保证：

- 从任务开始就记录轨迹
- 自动捕获输入文件和中间产物
- 自动记录重要文件版本
- 自动记录 token 消耗
- 结束时动态判断脱敏策略
- 先给专家看脱敏预览
- 专家确认后才生成最终包
- 最终包只包含脱敏后的文件和可交付的轨迹信息

## 事后补采的限制

如果任务结束后才开始采集，系统只能做降级处理：

- 只能收集当前工作区现有文件
- 如果没有历史版本，就只能保留单版本
- token 消耗可能不完整
- 中间过程可能无法恢复
- 文件来源和生成步骤可能不准确

因此，推荐产品流程是：

```text
任务开始时启用采集
任务结束时脱敏确认并打包
```
